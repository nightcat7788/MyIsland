### ④ 睡眠 —— ❌ 查出**真缺陷**（已修）

| 项 | 结果 |
|---|---|
| 调用 | `ControlService.Sleep()` → `SetSuspendState` —— Windows **记录了调用**（`Microsoft-Windows-Kernel-Power` 事件 187「用户模式进程尝试通过调用 SetSuspendState 更改系统状态」，20:32:28 与 20:32:57 各一次） |
| 但 | **没有真的进入睡眠**：既无事件 42（进入睡眠）也无 506（进入新型待机）⇒ 机器始终醒着 |
| 根因 | `powercfg /a` 显示本机**只有「待机 (S0 低电量待机) 连接的网络」**（Modern Standby），**没有 S3**；这类机器上 `SetSuspendState` 是个 no-op |
| 附带发现 | 产品**把 `SetSuspendState` 的返回值直接丢掉**了 ⇒ 即使调用失败，用户点了「睡眠」也**什么都不会发生、也没有任何提示** |

**修法（已落地）**：
- `ControlService.SupportsClassicSleep`（`IsPwrSuspendAllowed`）判定本机有没有传统睡眠；
- 不支持时**「睡眠」按钮不出现**（与亮度同一口径：不留一个点了没反应的按钮），同行给出原因；
- `ControlService.Sleep()` 改为返回 `(Ok, Message)`，失败/不支持都**说清楚为什么**，不再吞掉结果。

### 附带确认：当前进程权限与电源能力

| 项 | 值 | 含义 |
|---|---|---|
| `SeShutdownPrivilege` | **HELD** | 睡眠 API **本身**不需要提权就能调 |
| `IsPwrSuspendAllowed()` | **False** | 但本机**没有传统睡眠**（S0 新型待机）⇒ 调用了也不会睡 |
| 唤醒机制 | 计划任务 `WakeToRun` 实测 20:33:25 触发成功（`lastResult=0x0`） | 休眠测试的自动唤醒链路本身是通的 |

### 结论

- **锁屏**：✅ 生效，有系统事件取证；
- **WLAN / 蓝牙**：⚠️ 写路径需要管理员；非管理员下**产品行为正确**（明确报错、拒绝、不动状态）；
- **睡眠**：❌ 在 S0 机器上无效 —— **已修**（按钮按能力消失 + 失败说原因）。

- 睡眠在**有 S3 的机器**（台式机 / 老笔记本）上验一次「真的睡过去并能唤醒」。

- 锁屏 / 睡眠 / WLAN 开关 / 蓝牙开关**永不自动执行**：它们会打断你手上的事或切断网络。

### ④ 睡眠 —— ❌ 查出**真缺陷**（已修）

| 项 | 结果 |
|---|---|
| 调用 | `ControlService.Sleep()` → `SetSuspendState` —— Windows **记录了调用**（`Microsoft-Windows-Kernel-Power` 事件 187「用户模式进程尝试通过调用 SetSuspendState 更改系统状态」，20:32:28 与 20:32:57 各一次） |
| 但 | **没有真的进入睡眠**：既无事件 42（进入睡眠）也无 506（进入新型待机）⇒ 机器始终醒着 |

- `ControlService.SupportsClassicSleep`（`IsPwrSuspendAllowed`）判定本机有没有传统睡眠；
- 不支持时**「睡眠」按钮不出现**（与亮度同一口径：不留一个点了没反应的按钮），同行给出原因；
- `ControlService.Sleep()` 改为返回 `(Ok, Message)`，失败/不支持都**说清楚为什么**，不再吞掉结果。

#### 机制已查清（读代码 + 实测）

| 项 | 机制 | 结论 |
|---|---|---|
| **WLAN 切换** | 产品用 `netsh interface set interface ... ` + `Verb = "runas"` ⇒ **它自己会弹 UAC**（每个动作一次），**不需要整个应用是管理员** | 之前那次"失败"的真实原因是 **UAC 被取消**，不是设计缺陷；产品已把失败原因弹 MessageBox 告知用户 ✓ |
| **蓝牙切换** | 产品直接控制 `bthserv` 服务（`ServiceController`），**没有** runas ⇒ 需要**进程本身**是管理员 | 普通权限下必然失败；产品如实提示「需要管理员权限才能开关蓝牙服务（可改用系统设置）」并提供「蓝牙」设置入口 ✓ 属**设计如此** |
| **失败可见性** | 两个命令的失败都会 `MessageBox.Show(原因)` | ✓ 不会"点了没反应" |

#### 本轮据此修掉的两处

1. **WLAN 的失败文案不再误导**：以前 UAC 被取消也报「需要管理员权限才能开关无线网络」，
   而取消授权只需重试一次、不必换权限。现在按 Win32 错误码区分：
   `1223 (ERROR_CANCELLED)` ⇒ 「已取消授权，未改动无线网络（UAC 弹窗点『否』或超时）」；
   其余 ⇒ 「需要管理员权限才能开关无线网络」。
2. **自检工具的读回时机**：产品的 `SetWlan` 是**异步**的（起一个 netsh 进程就返回），
   立刻读回会读到旧状态。工具改为**轮询等待状态真正变化**（最多 15 秒）再读，验的才是真实结果。
