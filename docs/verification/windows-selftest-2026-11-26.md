### ④ 睡眠 —— ❌ 查出**真缺陷**（已修）

| 项 | 结果 |
|---|---|
| 调用 | `ControlService.Sleep()` → `SetSuspendState` —— Windows **记录了调用**（`Kernel-Power` 事件 187，20:32:28 与 20:32:57 各一次） |
| 但 | **没有真的进入睡眠**：既无事件 42（进入睡眠）也无 506（进入新型待机）⇒ 机器始终醒着 |
| 根因 | `powercfg /a` 显示本机**只有「待机 (S0 低电量待机) 连接的网络」**（Modern Standby），**没有 S3**；这类机器上 `SetSuspendState` 是 no-op |
| 附带发现 | 产品**把 `SetSuspendState` 的返回值直接丢掉**了 ⇒ 即使调用失败，用户点了「睡眠」也**什么都不会发生、也没有任何提示** |

**修法（已落地）**：`ControlService.SupportsClassicSleep`（`IsPwrSuspendAllowed`）判定 ⇒ 不支持时**「睡眠」按钮不出现**
（与亮度同一口径：不留一个点了没反应的按钮），同行给出原因；`Sleep()` 改为返回 `(Ok, Message)`，失败/不支持都**说清楚为什么**。

### 这轮验证查出并修掉的四个真缺陷

**① 亮度不支持时留着一对死按钮**（`GetBrightness() ?? 50` 编了个基准值去写，**静默失败**）
⇒ 读不到时**整行不出现**，命令读不到就**直接返回**，不再用 `?? 50` 编值。

**② 睡眠在 S0 机器上无效**（`SetSuspendState` 是 no-op，返回值还被丢掉）
⇒ 按能力收按钮 + 返回 `(Ok, Message)`。

**③ netsh 输出编码随「有没有控制台」而变 ⇒ 无控制台时 WLAN 状态读成「未知」**
- netsh 有控制台时按 OEM 码页写（中文系统 = 936），**没有控制台时写 UTF-16LE**；
  而 .NET 读重定向输出默认按 UTF-8 解 ⇒ 在**无控制台的进程里**（提权进程、以及**真正的 WPF 应用**）
  解出来是乱码，状态列一个词都匹配不上 ⇒ 界面显示「未知」。
- 修法：`RunNetsh` 改取**原始字节**，解析端按候选编码逐个试（UTF-8 → OEM 码页 → UTF-16LE → Latin1），
  **第一个能解出状态列的就算数**；都解不出仍返回「未知」，不编造。
- 实测：修复前提权进程读「适配器 未知；连接 未知」，修复后读「适配器 已启用；连接 已连接」✓。

**④ 无线适配器被禁用后「找不到它」⇒ 能关不能开**
- .NET 的 `NetworkInterface` 枚举在适配器被禁用后可能**整个看不到它**（或类型退化成 Unknown）
  ⇒ 产品报「未找到无线适配器」⇒ **用户在应用里把 Wi-Fi 关掉后就再也开不回来**，只能去系统设置。
- 修法：`GetWirelessAdapterName()` 增加 netsh 兜底 —— `netsh interface show interface`
  **连被禁用的网卡也列** ⇒ 用它找出适配器名，于是「关掉 → 再打开」闭环。
- 实测：修复前「还原 失败: 未找到无线适配器」；修复后「还原 已下发 → 读回 启用」✓。
