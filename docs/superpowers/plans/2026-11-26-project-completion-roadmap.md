## 第九轮：Windows 端功能自检（实测跑出真缺陷）

**动机**：Windows 有一批平台专属能力（亮度 / WLAN / 蓝牙 / 静音 / 锁屏 / 睡眠 / 系统主题 / 夜灯 / 电源计划 /
清理内存 / 网络适配器 / 剪贴板历史 / 开机自启），它们是**带副作用的 OS 操作**，测试工程（零依赖、只跑纯逻辑）
把它们排除了 ⇒ **这一批能力长期没有任何功能验证**，只有「编译通过」这一层。

新增 `tools\win-selftest`（调的是**产品自己的服务**，同一份源文件链接进工具）+ `tools\win-selftest.ps1` 一键运行，
默认**只读**，锁屏 / 睡眠 / WLAN 开关 / 蓝牙开关**永不自动执行**（标「需人工」），产物落到 `docs\verification\`。

### 自检跑出来的真缺陷（已修）

**亮度行留着一对死按钮**。Dxva2 的亮度接口只对外接显示器/部分驱动有效，**笔记本内置屏读不到**；
而产品代码用 `GetBrightness() ?? 50` **编了一个基准值**去调 `SetBrightness`，**静默失败**（返回值被忽略），
界面上那对 −/+ 按钮看起来还能点。修法（与仓库里 WLAN / 夜灯的既有口径一致）：
- `PanelData` 加 `HasBrightness`：读不到 ⇒ **整行不出现**（总纲 §1「平台不支持 ⇒ 直接不出现」）；
- 命令读不到就**直接返回**，不再用 `?? 50` 编值；
- 需要调亮度时，系统的「显示」快捷入口（ms-settings:display）就是正路。

### 自检同时**证伪**了两个我原本怀疑的点（如实记）

- **夜灯不是缺陷**：注册表键存在（`default$windows.data.bluelightreduction.bluelightreductionstate`），
  但**没有值**（本机从没配置过）⇒ 产品读不到状态。产品早就有处理：照样显示卡片，
  点了写不进去就**带去系统设置**开启（`ms-settings:nightlight`）—— 比我以为的周全。
- **清理内存是真的能跑**：本机实测释放 498 MB（另一次 1332 MB），返回的是实际释放量，
  超时则返回「未知」而不是 0 —— 不拿 0 冒充「没清到」。
