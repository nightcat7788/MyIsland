# 阶段 2：Windows 展开面板对齐 mac 版 —— 设计规格

日期：2026-11-26
状态：设计已定；实施分批进行（见 §7 顺序）
范围：`src/Island.App/`（Windows 侧改动）+ 规格与测试
基准：**以 mac 版现有实现为准**（总纲 §1）

---

## 1. 目标

总纲 §1 的判定标准之一是「视觉规格一致 —— 同一元素在两端的字号、环径、间距、分隔线、配色口径相同」，
§4.3 指出展开面板的页签顺序/图标/页内分区/视觉规格属于阶段 2 的核心。

阶段 1（收起态胶囊）已经做完了同一件事：把 mac 的排版常量抄进规格类，由 Windows 侧断言符合。阶段 2 沿用这个办法。

## 2. 三条取舍规则（本阶段据此裁决所有差异）

**规则一：共享 UI 对齐几何与结构，保留各自的配色身份。**
字号、字重、间距、圆角、分区顺序、分隔线位置、页签形态与顺序、图标语义 —— 这些**对齐**。
但**配色策略保留 Windows 的「暗色科技」口径**（一屏一主角 + Accent 强调色；阶段 1 已定）。
mac 的「按资源着色」（CPU #2E9BFF / 内存 #4FE3D7 等）**不引入** —— 那是 mac 自己的视觉身份。

**规则二：平台专属能力不互相搬运（总纲 §1）。**
Windows 侧保留：设置齿轮、收起 ✕、剪贴板页的「文件」列、控制页。
macOS 侧保留：屏幕页（DDC）、菜单栏、触感反馈、自动跟随窗口。
两端**呈现规则统一**（页签按「共享页签在前、平台专属页签在后」排布），差异在能力清单里公开。

**规则三：不合并两套渲染层。**
mac 自带 `src/Island.Avalonia/RenderKit.cs`（18 KB），Windows 是 `src/Island.App/Controls/RenderKit.cs`（38 KB），
**不是同一份代码**。合并是重构，不属于一致性对齐。本阶段只保证**调用点参数**一致。

## 3. 目标规格（以 mac 现有实现的数值为准）

### 3.1 顶栏

| 项 | mac（目标） | Windows（现状） | 动作 |
|---|---|---|---|
| 页签形态 | **图标 + 文字**（图标 14px、间距 5、文字 12px） | 纯图标 16px | Windows 改成图标 + 文字 |
| 页签顺序 | 监控 │ 剪贴板 │ 屏幕(仅mac) │ 设备(仅mac) | 监控 │ 剪贴板·文件 │ 设备 │ 控制 | 共享页签顺序**已一致**；mac 把「屏幕」挪到末尾，平台专属页签统一在最后 |
| 页签激活态 | Accent 20% 底 + 圆角 8 + 文字 Text / 图标 Accent | 主题 TabBtn 样式 | 按 mac 口径调 |
| 时间 | **右侧**，12px Regular（比例字体） | **居中**，12.5px Bold 等宽 | Windows 挪到右侧并改字号字重 |
| 右侧按钮 | 无（mac 靠移开鼠标收起） | 齿轮 + ✕ | **保留**（规则二） |
### 3.2 面板外框

| 项 | mac | Windows | 动作 |
|---|---|---|---|
| 圆角 | 20 | 20 | 已一致 |
| 背景 | 不透明 Surface | 液态毛玻璃 + 顶部辉光 | **保留 Windows**（规则一） |
| 内容内边距 | 左右 18 / 上 14 / 下 18 | 左右 16 / 上 10 / 下 12 | Windows 改成 mac 的值 |

### 3.3 监控页

mac 是 **2×2 卡片栅格**（卡片宽 256、列间距 12、排间距 12、上排高 181、下排高 156）；
Windows 是「左仪表栏 + 右进程卡」。布局重排是本阶段最大的一块，分两批做。

**批次 1（改调用点参数即可，视觉收益大）**：

| 项 | mac | Windows 现状 | 动作 |
|---|---|---|---|
| 字号阶梯 | 14 / 12 / 11 / 10 / 9 | 36 / 17 / 12.5 / 12 / 11 / 10 / 9.5 | Windows 收敛到 mac 的阶梯（**放弃 36px 主读数与 17px 行读数**） |
| 卡片标题 | 12px SemiBold Text + 12×12 图标 + 标题下 1px Hairline（左右内缩 15） | 10px Tertiary，无图标无分隔线 | 按 mac 口径改 |
| 行标签 | 10px TextDim | 12px TextDim | 改 |
| 行数值 | 14px SemiBold | 17px Bold 等宽 | 改 |
| 进度条 | 高 4px 圆角 2 | 高 3px | 改 |
| 走势线 | 笔宽 1.4px、框高 14 | 笔宽 1.2px | 改 |
| 进程榜标题 | 「占用最高 · CPU/内存」12px SemiBold | 「进程」10px Tertiary | 改 |
| 榜分段控件 | 96×20 圆角 6，选中段 Accent 实心 | 80×22 圆角 11，选中段半透明 | 改 |
| 进程榜行 | 行距 21、最多 5 行、图标 15×15、名称 11px、数值 11px SemiBold | 行距 34、最多 6 行、图标 16×16、名称 12px、数值 12.5px | 改 |
| 榜空态 | 10.5px Tertiary，区分「未采集」/「暂无」 | 12px「采样中…」 | 改 |
| 底部健康状态行 | 9px：「读数正常」/「⚠ 问题列表」 | 无 | 新增 |
| 分隔线位置 | 只在**卡片内标题下** | 区块之间 | 改位置 |
| GPU 角标 | 占用卡右上 10px SemiBold | 无 | 新增 |

**批次 4（要重排整页）**：2×2 卡片栅格本身 + 速度卡两行结构 + 卡底信息位（网络类型 / 电池）
+ 流量条改对数刻度（2MB/s 满格）。

### 3.4 剪贴板页

mac：单区两列（列表 246 + 间距 20）+ 分类标签栏 + 头部计数/导出/清空 + 自绘 3px 覆盖式滚动条 + 自绘右键浮层。
Windows：两卡片（剪贴板 + 文件列）+ XAML ScrollViewer + 系统右键菜单。

- **批次 1**：行高 32→30、时间改相对时间 9.5px 比例字体、行内 × 12px 与热区、「+N 行」9.5px、
  行图标改 5px 类型彩点、正文按类型分渲染（11 / 10 / 10.5 等宽 / 10.5）与 14×14 色块、空状态文案与左上定位。
- **批次 5（要重排 + 自绘控件）**：分类标签栏、头部计数/导出/清空、单区两列、自绘滚动条、自绘右键浮层。
- 「文件」列是 Windows 专属能力（规则二保留），但页签名应与 mac 一致写「剪贴板」。

### 3.5 设备电量页

mac：132×150 卡片网格，每行 3 张，面板高度自适应；Windows：每页 5 列大环 + 翻页器。

- 环直径 60 / 线宽 5 / 弧起点与方向 / 分档阈值 ≤20 ≤40 —— **两端已一致** ✓
- **批次 3（要改）**：布局改卡片网格（去掉翻页器）、百分比 20+11 两行改 26 单串、状态行 9.5→10、
  空状态改 mac 文案 11.5px 左上定位、改用共享的 `RenderKit.Ring`（现在自写 `Arc()`，绕过了死区与轨道透明度口径）。
- **保留**（Windows 专属）：设备类型矢量图标集、充电角标、档位文字。
  （mac 侧缺图标集与 LevelText 渲染 —— mac 侧另补，不在本阶段。）

### 3.6 小形象款式（§4.2）

mac 8 款：classic / mono / cat / robot / pixel / **alien / ghost / frog**；Windows 只有前 5 款。
以 mac 为准 → **Windows 补齐后 3 款**（几何参数见附录）。

## 4. 规格的守护方式（沿用阶段 1 的做法）

新增 `src/Island.App/Controls/ExpandedPanelSpec.cs`：**纯计算、无 WPF 依赖**的规格类，
把 mac 的目标常量抄进去（字号、间距、圆角、页签顺序、分区高度……），
Windows 侧实现引用它，测试工程链接它并断言「实现符合规格」。

这样规格不是文档里的数字，而是**代码里被门禁守着的数字** ✓
（阶段 1 的 `CompactSpec` / `CompactLayout` + `CompactSpecTests` / `CompactLayoutTests` 同款）。

## 5. 验收标准

1. `dotnet build Island.sln -c Release`：**0 警告 0 错误**
2. `Island.Tests`：**全过**（含新增的规格断言）
3. `src/Island.Avalonia/**`：**本阶段零改动**（mac 侧缺的图标集/LevelText 渲染另立一轮）
4. 顶栏页签形态、时间位置与字号、监控页字号阶梯、设备页卡片网格 —— 与本规格一致
5. **配色身份保持不变**：不引入 mac 的按资源配色，不改 Windows 主题 token
6. 平台专属能力（齿轮 / 收起 / 文件列 / 控制页）保持可用

## 6. 明确不做

- 不合并两套 RenderKit（重构）
- 不引入 mac 的按资源配色（配色身份）
- 不把 Windows 的齿轮 / 收起 / 文件列 / 控制页搬到 mac（平台专属能力）
- 不删 mac 的屏幕页（平台专属能力）
- 不动收起态（阶段 1 已完成）

## 7. 实施顺序（按收益/风险排序）

| 批次 | 内容 | 性质 |
|---|---|---|
| 批次 1 | 顶栏（页签图标+文字、时间右对齐）、面板内边距、监控页字号阶梯与卡片标题/分隔线、进程榜行距与字号 | 改常量与 XAML，**低风险** |
| 批次 2 | 小形象补齐 3 款 | 纯新增绘制，**中风险**（几何要对得上） |
| 批次 3 | 设备页卡片网格（去掉翻页器、改用 `RenderKit.Ring`） | 重排布局，**中风险** |
| 批次 4 | 监控页 2×2 卡片栅格 + 速度卡重构 | 重画整页，**高工作量** |
| 批次 5 | 剪贴板页单区两列 + 标签栏 + 自绘滚动条/右键浮层 | 重排 + 自绘控件，**最高工作量** |

批次之间互不阻塞，每批各自过门禁。
